# ADR-002: Semgrep для SAST

## Статус
Accepted

## Контекст
Нужен инструмент статического анализа безопасности для команды из 20 разработчиков.
Стек: Python, JavaScript, Go, Java. CI/CD на GitHub Actions.

## Проблема
Ручной code review не масштабируется — нужно автоматизировать поиск типовых уязвимостей (SQLi, XSS, hardcoded secrets) на этапе PR.

## Варианты

| Вариант | Pros | Cons |
|---------|------|------|
| **Semgrep** | Open source, кастомные правила, 30+ языков, быстрый | False positives |
| **SonarQube** | Quality + Security, много правил | Тяжёлый, сложная настройка, нет кастомных правил |
| **CodeQL** | Анализ на графе, глубокий поиск | Только для 10 языков, медленный |
| **Fortify** | Enterprise уровень | Очень дорого, сложный |

## Решение
**Выбрали Semgrep**.

Почему:
- Кастомные правила — можно писать под свой стек
- Быстрый анализ (секунды на PR)
- Open source
- Интеграция в CI/CD через GitHub Actions
- Поддержка 30+ языков

## Trade-offs
- **Чем пожертвовали:** Глубиной анализа (CodeQL находит больше) ради скорости и простоты
- **Принятые риски:** False positives требуют ручного triage
- **Компенсирующие меры:** Регулярная настройка правил, дополнение DAST и manual review

## Последствия
- + Быстрый SAST в CI/CD
- + Кастомные правила под проект
- + Бесплатно
- - Нужен инженер для написания правил
- - Не заменяет manual review
- - False positives требуют внимания
