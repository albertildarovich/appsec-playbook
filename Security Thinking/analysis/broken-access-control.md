# Почему Broken Access Control сложнее XSS

## Проблема

XSS — это техническая уязвимость. Есть чёткое "как искать" и "как исправить".
Broken Access Control — это логическая уязвимость. Нет универсального решения.

## Почему BAC сложнее

### 1. XSS можно автоматизировать. BAC — нет.
SAST ищет XSS по паттернам: `<script>`, `innerHTML`, опасные функции.
BAC требует понимания бизнес-логики: кто кому что должен видеть.

### 2. XSS — один тип. BAC — множество.
- IDOR (горизонтальный / вертикальный)
- Mass assignment
- Privilege escalation
- Path traversal
- Missing function-level access control

### 3. XSS видно в ответе. BAC — не всегда.
XSS: отправил `<script>` — получил `<script>` в ответе.
BAC: отправил `GET /api/orders/123`, получил `200 OK`. Но имел ли user 123 право на этот заказ? Без контекста не понять.

### 4. BAC требует понимания бизнеса
```
Роль "менеджер" может:
- Смотреть заказы своего отдела? Или любые?
- Смотреть заказы только за текущий месяц? Или любые?
- Может ли менеджер отменить заказ? Или только изменить статус?
```

Без ответов на эти вопросы невозможно проверить BAC.

## Как я подхожу к BAC

### 1. Начинаю с DFD и Threat Modeling
- Trust boundaries
- Data flows
- Где происходит проверка прав?

### 2. Спрашиваю разработчиков / Product Owner
- "Какие роли есть в системе?"
- "Какие действия может каждая роль?"
- "Какие данные видит каждая роль?"
- "Есть ли исключения из правил?" (вот тут часто BAC и кроется)

### 3. Тестирую вручную
- Перебираю ID (1, 2, 3, 1000)
- Меняю роль в запросе
- Пробую методы: `GET` → `POST` → `PUT` → `DELETE`
- Пробую другие Content-Type (XML вместо JSON)

### 4. Автоматизирую где могу
- **Autorize** (Burp extension) — автоматическая проверка IDOR
- **Custom Semgrep rules** — поиск missing ownership checks

## Вывод

XSS побеждается технологиями (CSP, encoding, sanitization).
BAC побеждается только архитектурой + культурой code review.

Поэтому OWASP Top 10 2021 поставил BAC на #1.
Не потому что он опаснее XSS (хотя и это спорно), а потому что его сложнее найти и исправить.
