# ADR-002: Выбор Semgrep для SAST

## Контекст
Нужен инструмент статического анализа безопасности. Требования: поддержка нескольких языков, кастомные правила, интеграция в CI/CD.

## Рассматриваемые варианты

| Вариант | Pros | Cons |
|---------|------|------|
| **Semgrep** | Open source, кастомные правила, 30+ языков, быстрый | False positives |
| **SonarQube** | Quality + Security, много правил | Тяжёлый, сложная настройка, нет кастомных правил |
| **CodeQL** | Анализ на графе, глубокий поиск | Только для 10 языков, медленный |
| **Fortify** | Enterprise уровень | Очень дорого, сложный |

## Решение
**Выбрали Semgrep**.

Почему:
- Кастомные правила — можно писать под свой стек
- Быстрый анализ (секунды на PR)
- Open source
- Интеграция в CI/CD через GitHub Actions
- Поддержка 30+ языков

## Какие угрозы закрываем

| Угроза | Как закрыли |
|--------|-------------|
| XSS, SQLi | Встроенные правила OWASP |
| Hardcoded secrets | Свои правила для проекта |
| Insecure crypto | Правила на MD5, SHA1, ECB |
| Dangerous functions | eval, exec, innerHTML |

## Какие риски остаются

| Риск | Контрмеры |
|------|-----------|
| False positives | Регулярная настройка правил |
| Не все уязвимости находит | Дополнять DAST и manual review |
| Правила нужно обновлять | Периодический review ruleset |

## Последствия

- + Быстрый SAST в CI/CD
- + Кастомные правила под проект
- + Бесплатно
- - Нужен инженер для написания правил
- - Не заменяет manual review
- - False positives требуют внимания
