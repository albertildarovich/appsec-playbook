## Trust Boundaries (границы доверия)

| # | Граница | Между | Уровень доверия меняется |
|---|---------|-------|--------------------------|
| 1 | **Boundary 1: Браузер → Интернет → Сервер** | Пользователь/Админ (неконтролируемая среда) → Сервер Juice Shop | **Высокий** — браузер и интернет не контролируются. На сервере нужно валидировать всё, что пришло от клиента (XSS, подмена запросов, JWT) |
| 2 | **Boundary 2: Сервер → Внешние API** | Сервер Juice Shop → Платёжная система / LLM API | **Высокий** — данные уходят на внешние серверы (номера карт, чаты). Риск утечки и компрометации |
| 3 | **Boundary 3: Сервер → Data Stores (внутренний контур)** | Сервер Juice Shop → SQLite / File System | **Средний** — DB и файлы на том же сервере, но SQLi нарушает эту границу |

## External Entities (внешние сущности)

| # | Сущность | Описание |
|---|----------|----------|
| 1 | **Пользователь (браузер)** | Клиент магазина. Взаимодействует через UI/API. Неконтролируемая среда |
| 2 | **Администратор (браузер)** | Управляет магазином через админ-панель. Тоже внешняя сущность |
| 3 | **Платёжная система** | Обработка платежей Deluxe Membership. Внешний сервер |
| 4 | **LLM API (внешняя)** | Чат-бот. Пока неактивен, но данные будут уходить на внешний сервер |

## Выводы

- **Самая критичная граница:** Boundary 1 (Браузер → Сервер) — браузеру и интернету нельзя доверять. Вся валидация должна быть на сервере
- **Самая опасная уязвимость на границах:**
  - Boundary 1: XSS в поиске, подмена запросов, JWT alg:none
  - Boundary 2: Утечка данных карт в платёжную систему
  - Boundary 3: SQLi — позволяет миновать границу между процессами и БД
- **Граница 3 — внутренняя:** хотя SQLite на том же сервере, SQLi ломает эту границу и даёт доступ к чужим данным
