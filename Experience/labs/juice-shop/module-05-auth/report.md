## Logout

**Что проверили:**
- В браузере: JWT удаляется из localStorage (✅ клиентская очистка работает)
- curl GET `/rest/user/logout` → **HTTP 500** (серверный endpoint не работает)
- Тот же JWT после logout → HTTP 200 на `/api/Users` (токен жив)

**Практическое подтверждение:**
Ты разлогинился в браузере, я проверил твой старый JWT — HTTP 200, все 26 пользователей с хешами паролей. Токен не был инвалидирован.

**Результат:**
- ❌ JWT не инвалидируется на сервере — токен живёт вечно
- ❌ Нет blacklist'а токенов
- ✅ UI-очистка localStorage работает, но не защищает от атакующего с украденным токеном

**Риск:** Critical (нет server-side инвалидации сессии)

---

## Reset Password

**Что проверили:**
- Страница `/#/forgot-password` — существует, но сломана (поля задизейблены)
- curl POST `/rest/user/reset-password` → заблокирован (anti-fraud защита — только с localhost)
- В локальной сборке reset password не работает без настроенного email-провайдера

**Результат:**
- ❌ UI есть, но не работает — Security Misconfiguration
- ✅ Anti-fraud защита от внешних запросов (но это не поможет, если атакующий на том же хосте)
- ❌ Невозможно протестировать механизм безопасности reset password в локальной сборке

**Риск:** Medium (функционал отключён, но UI вводит в заблуждение)

---

## MFA

**Что проверили:**
- В приложении нет страницы настройки двухфакторной аутентификации
- В JWT payload есть поле `totpSecret` — предполагается поддержка TOTP, но UI отсутствует
- MFA не используется и не может быть включена

**Результат:**
- ❌ MFA отсутствует
- ❌ Даже при admin-доступе нет двухфакторной защиты
- ✅ В payload JWT есть поле `totpSecret` — возможно, задел на будущее

**Риск:** High (особенно в сочетании с отсутствием rate limiting и бессрочными JWT)
