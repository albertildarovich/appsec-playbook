## Что делал в контексте безопасности

### 1. Security Code Review
Code Review был обязательной частью процесса перед merge.
Без approve ревьювера — никакой PR не попадал в main.

**Связь с Playbook**: [Code Review](../../Engineering/code-review/README.md)

**Что понял**:
- Разработчики лучше воспринимают feedback, если показываешь fix, а не просто указываешь на проблему
- Чек-лист ускоряет review в 2-3 раза
- Semgrep в CI находит ~30% проблем, остальное — только глазами

### 2. Keycloak — RBAC настроил
Настраивал Keycloak для управления доступом:
- Ролевая модель (RBAC)
- SSO для нескольких приложений
- Интеграция с LDAP

**Связь с Playbook**: [Authorization](???)

**Что понял**:
- Role explosion — реальная проблема. Ролей становится слишком много
- RBAC + ABAC вместе дают гибкость
- Keycloak мощный, но сложный. Для простых сценариев лучше Auth0 / Firebase

## Как это повлияло на мой подход к AppSec

1. **70% проблем — культура, 30% — инструменты**. Самый мощный инструмент — это review-культура в команде.
2. **Безопасность продаётся через business value**. "Мы должны шифровать" — плохо. "Утечка данных стоит $5M" — хорошо.
3. **DevSecOps не работает без DevOps**. Сначала автоматизируй deployment, потом добавляй security.
4. **Разработчики не враги**. Они не хотят делать небезопасно. Они хотят быстро делать фичи. Задача AppSec — показать путь, где быстро и безопасно совпадают.
