## Что даёт опыт разработки

### 1. Понимаю, как думает разработчик
Я знаю, почему разработчик пишет так, а не иначе.
Почему он "забыл" про prepared statements (спойлер: не забыл, а писал быстро).
Почему не поставил rate limiting (спойлер: deadline).

Это позволяет:
- Говорить на одном языке
- Предлагать реалистичные fix'ы, а не теоретические
- Понимать, какие рекомендации примут, а какие — нет

### 2. Понимаю контекст
Code Review — это не просто "тут уязвимость".
Это:
- Этот PR деплоится сегодня вечером
- Разработчик работает в этом модуле первый раз
- deadline через 2 часа

Good cop: "Понимаю, сроки горят. Давай пофиксим вот это (критичное) сейчас, а это (medium) — в следующем спринте."

### 3. Понимаю архитектуру
Team Lead опыт = понимание всей картины:
- Как микросервисы общаются
- Где данные хранятся
- Как устроен CI/CD

Это позволяет проводить Threat Modeling на уровне архитектуры, а не отдельных endpoint'ов.

### 4. Могу читать код на разных языках
PHP → JavaScript → Python → SQL → Bash
Не нужно спрашивать разработчика "что тут происходит". Я вижу сам.

## Что даёт опыт QA

### 1. Системный подход к тестированию
QA учит:
- Пограничные случаи
- Негативные сценарии
- "А что, если пользователь сделает вот так?"

Это напрямую переносится в security testing.

### 2. Документирование багов
QA учит писать понятные багрепорты:
- Шаги воспроизведения
- Ожидаемый / фактический результат
- Среда
- Приоритет

В security то же самое. Только stakes выше.

## Вывод

Опыт разработки + QA = AppSec, который:
- Понимает контекст
- Говорит на языке команды
- Предлагает реалистичные решения
- Не ломает, а улучшает

Это и есть моё конкурентное преимущество.
