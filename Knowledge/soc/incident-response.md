# Incident Response для SOC L1

## Зачем это SOC-аналитику

Работа SOC-аналитика L1 — это обработка инцидентов: от получения алерта до закрытия тикета. Нужно:

- Понимать жизненный цикл инцидента.
- Уметь документировать каждый шаг.
- Знать принципы эскалации (что, кому, как).
- Владеть базовым сбором evidence.

## Жизненный цикл инцидента

```
Обнаружение (алерт, тикет, запрос)
        |
Регистрация (id, severity, owner)
        |
Триаж (TP/FP, критичность, приоритет)
        |
Анализ (контекст, timeline, root cause)
        |
Сдерживание (containment)
        |
Устранение (eradication)
        |
Восстановление (recovery)
        |
Извлечённые уроки (lessons learned)
        |
Закрытие тикета
```

## SANS PICERL

Модель из 6 фаз:

| Фаза | Описание | Задачи L1 |
|------|----------|-----------|
| Preparation | Подготовка: планы, инструменты, контакты | Обновить playbooks, проверить инструменты |
| Identification | Выявление: алерты, аномалии | Подтвердить/отклонить инцидент |
| Containment | Сдерживание: изолировать, не дать распространиться | Изолировать хост, отключить аккаунт |
| Eradication | Устранение: удалить вредонос, закрыть доступы | Удалить артефакты, сбросить пароли |
| Recovery | Восстановление: вернуть в строй | Вернуть хост в эксплуатацию |
| Lessons Learned | Уроки: что улучшить | Написать постмортем |

## Регистрация инцидента

Что фиксировать в тикете:

```
Инцидент ID:            INC-2026-0001
Обнаружен:              2026-08-04 03:15 UTC
Источник обнаружения:   SIEM (Wazuh), правило #100011
Активы:                 WS-001 (Windows 10), user: albert
Severity:               Средняя (3/5)
Статус:                 Open

Описание:
  10+ неудачных входов (Event 4625) с IP 185.220.101.2
  на пользователя albert за 15 минут.

Evidence:
  - Event IDs: 4625 x12
  - Source IP: 185.220.101.2
  - Время: 03:00-03:15 UTC
  - User: albert

Действия:
  1. Проверить успешный вход после неудач (4624) - нет
  2. Проверить др. хосты с тем же IP - нет
  3. Заблокировать IP на NGFW

Решение:  FP - атака не удалась, учётная запись не скомпрометирована
Закрыт:   2026-08-04 03:45 UTC
```

## Severity (критичность)

Классификация:

| Severity | Описание | Пример |
|----------|----------|--------|
| Critical | Компрометация данных, полный контроль | Ransomware, DCSync, доступ к базе |
| High | Компрометация учётной записи/хоста | Mimikatz, RDP-вход с правами админа |
| Medium | Подозрительная активность, failed logons | Brute force, сканирование |
| Low | Малозначимые алерты, policy violations | Неверный сертификат |

Матрица приоритета:

```
Severity x Asset Value x Дальность (reachability) = Priority

Asset Value: критичный сервер > рабочая станция > тестовый хост
Reachability: из интернета > из DMZ > изнутри сети

Пример:
  Brute force к Domain Controller из интернета = Critical
  Brute force к тестовой VM изнутри = Low
```

## Эскалация

Когда эскалировать:

1. Обнаружен TP с высокой критичностью (Critical/High).
2. Инцидент затрагивает критичные активы (DC, базы, финансовые системы).
3. Требуется реакция выше уровня L1 (форензика, сдерживание, юристы).
4. Неопределённость: не понятен масштаб/воздействие.

Кому:

```
Тикет-система: Jira / ServiceNow / TheHive
Старший аналитик (L2/L3): подозрительный C2, AD-компрометация
Сетевая команда: блокировка IP/домена
Владелец системы: подтвердить легитимность
Руководство: критичные инциденты (по SLА)
```

Что передавать:

```
- Инцидент ID + severity
- Timeline (что, когда, где)
- Evidence (события, IP, процессы, файлы)
- Уже выполненные действия
- Рекомендации по дальнейшим шагам
- Неопределённости/вопросы
```

## Сбор evidence

Правила сбора:

- Сохранять в порядке по времени (timeline).
- Документировать каждый артефакт.
- Сохранять неизменные копии (хеши SHA256).
- Не изменять систему до сбора данных (кроме сдерживания).

Что собирать на Windows:

```
- Журналы событий: Security, System, Application, PowerShell, Sysmon
- wevtutil export-log Security C:\evidence\security.evtx
- Процессы: tasklist /v
- Сеть: netstat -anob
- Автозагрузка: autorunsc
- Запланированные задачи: schtasks /query /fo csv
- Службы: sc query
- Открытые файлы: openfiles
- Prefetch: C:\Windows\Prefetch
- Amcache: C:\Windows\AppCompat\Programs\Amcache.hve
- Мусорная корзина
```

Что собирать на Linux:

```
- Журналы: /var/log/auth.log, /var/log/syslog, journalctl
- Процессы: ps auxf
- Сеть: ss -tunap
- Автозапуск: crontab -l, systemctl list-timers
- Пользователи: who, last, lastb, cat /etc/passwd
- Артефакты: bash_history, /tmp, /var/tmp
- Файлы с признаками изменений: rpm -Va / dpkg -V
```

Метаданные (для каждого артефакта):

```
Файл:       C:\Windows\System32\evil.dll
SHA256:     a1b2c3d4...
Размер:     512 KB
Время создан:  2026-08-03 14:22:33 UTC
Время изменён: 2026-08-03 14:22:34 UTC
Владелец:   DOMAIN\system
Откуда взят: копия при изоляции
```

## Типовая обработка распространённых алертов

### 1. Brute Force / Password Spraying

```
Признаки: Event 4625, 4771, множество с одного IP
Шаги:
  1. Подтвердить паттерн (количество, период, пользователи)
  2. Проверить успешные входы (4624) после попыток
  3. Проверить др. хосты с тем же IP (спрей?)
  4. Заблокировать IP на периметре
  5. Если учётка скомпрометирована - сбросить пароль, отключить сессии
  6. Документировать как инцидент (High, если успех)
```

### 2. Mimikatz / Credential Dumping

```
Признаки: Sysmon 10 (access to lsass), 4688 (mimikatz), 4656
Шаги:
  1. Подтвердить процесс, пользователя, хост
  2. Изолировать хост (отключить от сети)
  3. Собрать evidence (handle lsass, процессы, DLL)
  4. Сбросить пароли всех пользователей, побывавших на хосте
  5. Проверить lateral movement (входы с этого хоста)
  6. Эскалация на L2/L3 (возможна компрометация домена)
```

### 3. Phishing (пользователь перешёл по ссылке)

```
Признаки: письмо, переход, загрузка файла, запуск
Шаги:
  1. Получить письмо (заголовки, ссылку, вложение)
  2. Проанализировать: SPF/DKIM/DMARC, домен, репутация
  3. Проверить: пользователь переходил? что запускал? (прокси, EDR)
  4. Если запускал файл - собрать хеш, отправить в песочницу
  5. Если credentials введены - сбросить пароль, отключить сессии
  6. Оповестить пользователя, провести awareness
```

### 4. Новый пользователь-администратор

```
Признаки: Event 4720 (user created), 4728/4732 (added to Admins)
Шаги:
  1. Кто создал? Дата/время?
  2. Легитимная операция? (админ подтверждает)
  3. Если нет - заблокировать аккаунт, откатить изменение
  4. Проверить другие изменения за период
  5. Эскалация (возможна компрометация AD)
```

### 5. C2 Beacon (аномальные исходящие)

```
Признаки: регулярные соединения к внешнему IP, DNS-подозрения
Шаги:
  1. Подтвердить периодичность, IP/домен, процесс
  2. Проверить TI-репутацию (домен/IP)
  3. Изолировать хост
  4. Собрать процессы, сеть, службы
  5. Проверить другие хосты с тем же подключением
  6. Эскалация на L2/L3
```

## SLA (показатели)

Типовые SLA для SOC:

| Инцидент | Время реакции | Время решения |
|----------|---------------|---------------|
| Critical | 15 мин | 1 час |
| High | 30 мин | 4 часа |
| Medium | 1 час | 8 часов |
| Low | 4 часа | 24 часа |

Важные метрики:

- MTTA (Mean Time to Acknowledge) — среднее время взятия в работу.
- MTTR (Mean Time to Resolve) — среднее время решения.
- MTTD (Mean Time to Detect) — среднее время обнаружения.
- FP Rate — доля ложных срабатываний.
