# A02 — Cryptographic Failures

> **Суть:** Неправильное использование криптографии. Большинство проблем — не в алгоритмах, а в том, что их применяют не по назначению.
>
> **Главный вопрос:** Нужно ли восстанавливать данные?
> - **Нет** → Хеширование (Argon2id для паролей)
> - **Да** → Шифрование (AES-256-GCM)

---

## Быстрый чек-лист

- [ ] Пароли хешируются (Argon2id / bcrypt), а не через SHA-256?
- [ ] Пароли никогда не шифруются (AES не для паролей)?
- [ ] Salt уникален для каждого пользователя?
- [ ] Pepper (если используется) хранится отдельно от БД?
- [ ] Секреты не в коде, а в Vault / Secrets Manager?
- [ ] TLS 1.2+ с PFS (ECDHE)?
- [ ] Не отключена проверка сертификатов?

---

## Ключевые тезисы

| Тема | Тезис |
|------|-------|
| **Хранение паролей** | Argon2id (Memory Hard, защита от GPU). Не SHA-256, не AES |
| **Salt** | Уникален для каждого пользователя, не секрет, хранится в БД |
| **Pepper** | Общий секрет, хранится отдельно (Vault/HSM) |
| **Secrets Management** | Vault > Environment Variables > Hardcoded |
| **TLS** | 1.2/1.3 с ECDHE (PFS). Отключение проверки сертификата = MITM |
| **PFS** | Каждая сессия — временный ключ. Компрометация ключа сервера не расшифрует старый трафик |
