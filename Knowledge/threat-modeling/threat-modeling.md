# Threat Modeling

> Процесс поиска угроз до появления уязвимостей.  
> **Главная идея:** проектировать систему так, чтобы атаки было невозможно реализовать, а не искать баги в готовой системе.

---

## Процесс Threat Modeling

```
1. Определить Assets
       ↓
2. Построить Data Flow Diagram (DFD)
       ↓
3. Найти Trust Boundaries
       ↓
4. Определить Threat Actors
       ↓
5. Построить Attack Tree
       ↓
6. Применить STRIDE
       ↓
7. Оценить риски
       ↓
8. Выбрать Mitigations
```

---

## 1. Assets (Активы)

**Asset** — любой объект, потеря которого нанесёт ущерб компании.

### Бизнесовые Assets (то, что *действительно* ценно)
- деньги клиентов
- персональные данные
- платежи, заказы
- коммерческая тайна
- репутация компании
- непрерывность работы сервиса

### Технические Assets (то, что *защищает* бизнес)
- PostgreSQL, JWT, Refresh Token
- API Keys, TLS Certificates
- Vault, Kubernetes Secrets
- Docker Registry, исходный код
- WAF, CI/CD

> [WARN] PostgreSQL ценен не сам по себе, а потому что внутри находятся бизнесовые данные.

---

## 2. Trust Boundaries

**Trust Boundary** — граница, где меняется уровень доверия.  
Определяется не сетью, а **уровнем доверия**.

```
Browser → Backend         ← Trust Boundary есть
Backend → Database        ← тоже может быть Trust Boundary
Order → Payment Service   ← может быть как одна, так и две Trust Zone
```

### Что влияет на Trust Boundary
- разные команды, права доступа, секреты
- разные сертификаты, политики безопасности
- разные уровни доверия

### Zero Trust

> Даже если сервис внутри инфраструктуры — это не значит, что ему можно доверять.

Каждый сервис проверяет:
- кто к нему обращается
- что他可以 делать
- действительно ли имеет право

---

## 3. Threat Actors

- внешний злоумышленник
- внутренний сотрудник
- подрядчик, администратор
- скомпрометированный сервис
- вредоносное ПО, ransomware

---

## 4. Attack Tree

> Не думать *"Какие есть уязвимости?"*, а думать *"Как злоумышленник достигнет цели?"*

```
Получить товар бесплатно
├── Украсть аккаунт
├── Подделать оплату
├── Стать администратором
├── Обойти авторизацию
└── Обмануть сотрудника
```

Каждая ветка раскладывается дальше:

```
Украсть аккаунт
├── Phishing
├── Malware
├── XSS
├── Credential Stuffing
└── Украсть JWT
```

> Attack Tree строится **от цели к способам**, а не наоборот.

---

## 5. STRIDE + CIA

Модели **не конкурируют**, а отвечают на разные вопросы.

| Модель | Вопрос |
|--------|--------|
| **CIA** | Что защищаем? |
| **STRIDE** | Как можно атаковать? |

### CIA
- **C**onfidentiality — конфиденциальность
- **I**ntegrity — целостность
- **A**vailability — доступность

### STRIDE
- **S**poofing — подмена личности
- **T**ampering — изменение данных
- **R**epudiation — отказ от действий
- **I**nformation Disclosure — раскрытие информации
- **D**enial of Service — отказ в обслуживании
- **E**levation of Privilege — повышение привилегий

### Нарушение CIA — примеры

| | Угроза | Примеры |
|---|--------|---------|
| **C** | Чтение данных | SQL Injection, BOLA, утечка бэкапов, Phishing, Insider |
| **I** | Изменение данных | цена товара, роль, банковский счёт, статус оплаты |
| **A** | Лишение доступа | DDoS, удаление БД, ransomware, переполнение диска |

> Один Asset может атаковаться по всем направлениям.  
> PostgreSQL: украли (C), изменили (I), удалили (A).

---

## 6. Risk Assessment

```
Risk = Likelihood × Impact
Risk = Likelihood × Impact × Exploitability
```

- **Likelihood** — вероятность эксплуатации
- **Impact** — последствия для бизнеса
- **Exploitability** — насколько просто воспользоваться

>  **Нет риска без контекста.** Одинаковая CVSS может иметь разный приоритет.

---

## 7. Памятка для собеседования

1. Threat Modeling начинается **не с STRIDE**, а с понимания бизнеса
2. Сначала **Assets** → потом **DFD** → **Trust Boundaries** → **Threat Actors** → **Attack Trees** → **STRIDE** → **Risk** → **Mitigations**
3. Мысли через **цели злоумышленника**, а не через названия уязвимостей
4. Оценивай угрозы через **вероятность и влияние на бизнес**
5. **Убирать функциональность** часто безопаснее, чем её защищать
