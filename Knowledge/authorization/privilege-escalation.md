# Privilege Escalation

> Получение пользователем возможностей, которые изначально ему не предоставлены.

---

## Два основных типа

| Тип | Суть |
|-----|------|
| **Horizontal** | Доступ к ресурсам другого пользователя **с тем же уровнем привилегий** |
| **Vertical** | Получение возможностей **более привилегированной роли** |

---

## Horizontal Privilege Escalation

Пользователь получает доступ к ресурсам другого пользователя того же уровня.

```
USER
  │
  ▼
Другой USER (тот же уровень)
```

Уровень привилегий не изменился. Изменился **только объект доступа**.

### Примеры

Получение:
- чужого профиля
- чужого заказа
- чужого документа
- чужого счёта
- чужой корзины

```http
GET /orders/124   # вместо /orders/123
```

### Типичная причина

Отсутствует проверка **владельца объекта**:

```java
// [NO] Опасно
repository.findById(id);

// [OK] Нужна проверка
if (currentUser.id != order.ownerId) {
    throw new ForbiddenException();
}
```

---

## Vertical Privilege Escalation

Пользователь получает возможности **более привилегированной роли**.

```
USER
  │
  ▼
ADMIN
```

или

```
Manager
  │
  ▼
Administrator
```

### Примеры

Обычный пользователь получает доступ:

```http
GET /admin/users
DELETE /admin/user/15
POST /admin/settings
```

### Типичная причина

Некорректная или отсутствующая **проверка роли / разрешений**.

---

## Аналогия

Представим офис:

```
10 этаж → CEO
 5 этаж → Managers
 1 этаж → Employees
```

- **Horizontal** — сотрудник первого этажа ходит по кабинетам других сотрудников первого этажа
- **Vertical** — сотрудник первого этажа получает доступ на этаж руководства

---

## Связь с IDOR

**Классический IDOR практически всегда приводит к Horizontal Privilege Escalation:**

```http
GET /users/15   →   GET /users/16
```

Если сервер не проверяет владельца объекта, пользователь получает доступ к данным другого пользователя.

### Но не каждая Horizontal Privilege Escalation — IDOR

```http
GET /reports?department=finance   →   GET /reports?department=hr
```

Здесь пользователь получает доступ к чужим отчётам за счёт изменения параметра запроса — это тоже нарушение авторизации. Но это **не классический Direct Object Reference**, так как отсутствует прямое обращение к объекту по идентификатору.

## Как классифицировать проблему

При анализе задавай вопросы в таком порядке:

```
┌────────────────────────────────────────┐
│ Есть ли нарушение контроля доступа?    │
└───────────────┬────────────────────────┘
                │ да
                ▼
┌────────────────────────────────────────┐
│ Связано ли с отсутствием проверки      │
│ доступа к конкретному объекту?         │
└───────────────┬────────────────────────┘
                │ да → IDOR
                ▼
┌────────────────────────────────────────┐
│ Доступ к объектам другого пользователя │
│ того же уровня?                        │
└───────────────┬────────────────────────┘
                │ да → Horizontal PE
                ▼
┌────────────────────────────────────────┐
│ Получены возможности более высокой     │
│ роли?                                  │
└───────────────┬────────────────────────┘
                │ да → Vertical PE
```

## Что искать во время Code Review

- Можно ли изменить идентификатор объекта?
- Проверяется ли владелец объекта?
- Проверяется ли роль пользователя?
- Проверяются ли разрешения (permissions)?
- Может ли пользователь обратиться к административным API?
- Можно ли получить доступ к данным другого пользователя?

---

## Практические правила

| Правило | Относится к |
|---------|-------------|
| Проверять владельца объекта на каждом endpoint | Horizontal |
| Проверять роль/permissions на каждом admin endpoint | Vertical |
| Default deny: без явного разрешения — запрет | Оба типа |
| НЕ использовать роль из запроса/тела/JWT без серверной проверки | Vertical |
| НЕ полагаться на «сложность» ID (UUID не защищает) | Horizontal |

---

## Ключевые мысли

1. **Horizontal** — доступ к чужим объектам при сохранении своего уровня привилегий
2. **Vertical** — получение возможностей более привилегированной роли
3. **IDOR** чаще всего является причиной **Horizontal** Privilege Escalation
4. **Не каждая Horizontal Privilege Escalation является IDOR**
